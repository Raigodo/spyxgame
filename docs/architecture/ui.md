# UI

Read before changing a screen, the header, toasts or dialogs, or before writing a game page. The UI is a thin layer on the [Room](./room.md): it reads stores, calls intents and shows the result.

## Stack

shadcn/ui (`base-nova`, built on Base UI), Tailwind 4, Phosphor icons, sonner for toasts. Components live in `src/ui/components/ui/` (generated by the shadcn CLI; do not hand-edit them). Dark mode follows the system setting (`prefers-color-scheme`); there is no toggle. Mobile first. Minimal: text, spacing, one primary action per screen.

## Where things are

```
src/ui/
  room-provider.tsx   joins on mount, leaves on unmount; connecting / failed / ended screens
  room-navigator.tsx  sends the tab to the lobby or the active game's page
  room-status.tsx     the full-page states
  shell/              AppShell, RoomHeader, HeaderSlot, ConnectionDot, RoomToasts
  players/            PlayersMenu (header popover), PlayersList (shared with the lobby)
  lobby/              LobbyScreen, GameLauncher, RenameForm, StarterForm, Section
  game/               announcements (dialog), Panel/Hint/Problem/Callout
  entry/              the /room landing page
  game-shell.tsx      one game's header title, End button, pause banner, dialog host
```

Routes: `/room` (create or join), `/room/[roomId]` (lobby), `/room/[roomId]/[game]` (a game). Hooks: `useStore`, `useRoom`, `useGame`, `useCommand`.

## The header

One header for the whole room: connection dot and room code (click copies the invite link), a **slot** for the page, the Players button, Leave. A page fills the slot with `<HeaderSlot>`: a title (`mr-auto` keeps it left) and quick actions ("End game"). The header is for navigation and quick menus. Anything that is part of the task (adding words, game settings) lives in the page.

## Feedback rules

| Kind                            | Used for                                                                                                             |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Toast (sonner)                  | Quiet passing news: joined, back, left, removed, new host, failed actions. Never about yourself, never on first load |
| Dialog                          | A moment that needs attention: a winner, a reveal. One at a time, queued, always closable                            |
| Header dot and disabled buttons | Connection state (`room.sync`). No toast, no overlay                                                                 |
| Full page                       | This tab cannot be in the room: removed, opened in another tab, full, could not join                                 |

Host actions are disabled until `room.sync` is `ready`.

## Writing a game page

Wrap nothing: `GameShell` already gives the header title, End button, pause banner and dialog host.

- Read with `useGame(def)`; render "Syncing…" while `view` is `undefined`.
- Layout with `Panel` (one bordered block), `Hint` (quiet text), `Problem` (a rejected action), `Callout` (a secret role, the word). Panels do not nest.
- A moment worth stopping for: ``useAnnouncement(winner ? { key: `winner:${round}`, title } : undefined)``. The key makes it show once. Call it before any early return.
- Notices (`emit` effects) are game-typed, so the page words them: `useEffect(() => handle.noticed.on((n) => toast(...)), [handle])`.
- The settings form is `StarterForm` plus `NumberField`.
