# Timer inventory

Every timer in `config.ts`: what it protects against, what a wrong firing costs, and whether it can shrink. "Destructive" means a wrong firing removes a live peer. Verify any change against `failover-timeline.test.ts`. A test requires every timer to have a row here.

| Timer                         | Default | Protects against                                                                                                                                                                       | If too short                                                                                                                                             | Shrink?                                                                                        |
| ----------------------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `candidateCollectionWindowMs` | 3s      | Guests noticing a dead host at different moments, so every candidate is registered before turns. Also the old host's reclaim grace, and the point where the suspected host is removed. | A late detector misses the list; the atomic claim still keeps one winner.                                                                                | Going lower shrinks the unstamped reclaim grace; split reclaim from the election window first. |
| `positionIntervalMs`          | 1.5s    | Candidate 0 dying after confirming. Position n waits n intervals.                                                                                                                      | Candidate 1 elects before seeing candidate 0's write. A host-document change cancels pending turns, so only write plus snapshot latency must be covered. | Fallback only.                                                                                 |
| `candidateConfirmWindowMs`    | 700ms   | Candidates that died during the window being elected. Each live candidate confirms, then waits this long for the others.                                                               | Slow confirms are missed; the atomic claim still keeps one winner.                                                                                       | Leave. Adds directly to failover time.                                                         |
| `ackTimeoutMs`                | 15s     | A peer in membership that never reads its signal inbox.                                                                                                                                | **Destructive**: deletes a slow-but-live peer. Vetoed when its data channel is active.                                                                   | Leave.                                                                                         |
| `messageRetentionMs`          | 1h      | Unconsumed signal docs piling up. Firestore TTL, lazy (hours).                                                                                                                         | A pending signal is deleted before it is read.                                                                                                           | Leave. Above `ackTimeoutMs` (tested).                                                          |
| `candidateRetentionMs`        | 1h      | Election candidate docs left behind.                                                                                                                                                   | A candidate disappears mid-election.                                                                                                                     | Leave. Above the election budget (tested).                                                     |
| `roomRetentionMs`             | 7d      | Abandoned rooms, memberships and host docs piling up.                                                                                                                                  | **Destructive**: a live session longer than this loses its membership or host doc.                                                                       | Raise it if sessions can run for days.                                                         |
| `offerTimeoutMs`              | 5s      | A host that never sends an offer.                                                                                                                                                      | **Destructive**: suspects a live host on slow ICE or a slow join.                                                                                        | No. Highest false-positive risk.                                                               |
| `reconnectTimeoutMs`          | 5s      | A guest waiting forever for a re-offer after its link died.                                                                                                                            | Drops the local entry early; an arriving offer recreates it.                                                                                             | Low value.                                                                                     |
| `reclaimWindowMs`             | 10s     | A refreshed host retrying `claimHost` while its old peer still looks present.                                                                                                          | The seat goes to someone else; the host just moves.                                                                                                      | With the candidate window (they overlap).                                                      |
| `iceBatchWindowMs`            | 300ms   | One signal doc per ICE candidate (a write, read and delete each).                                                                                                                      | Smaller batches, more docs. Too long delays link setup.                                                                                                  | Tune against real link-up time.                                                                |
| `probeIdleMs`                 | 10s     | A data channel that stays open but carries nothing. The host pings after this much silence.                                                                                            | **Destructive**: a briefly frozen tab is declared dead and re-linked.                                                                                    | Leave. At least `probeTimeoutMs` (tested).                                                     |
| `probeTimeoutMs`              | 5s      | The wait for the pong.                                                                                                                                                                 | **Destructive**: same.                                                                                                                                   | Leave.                                                                                         |
| `chunkBufferTtlMs`            | 30s     | Partial messages that never complete.                                                                                                                                                  | Large messages on slow links are dropped.                                                                                                                | Leave.                                                                                         |
| `commandTtlMs`                | 30s     | Commands waiting for an ack forever.                                                                                                                                                   | Commands expire during a failover and are lost.                                                                                                          | Only while above the failover budget (tested).                                                 |
| `recoveryWindowMs`            | 3s      | A new host publishing before slow guests offered their copies.                                                                                                                         | A fresher copy arrives after publishing and is dropped.                                                                                                  | No.                                                                                            |
| `recoveryMaxMs`               | 10s     | Recovery waiting forever for an unreachable guest.                                                                                                                                     | Same, for guests with slow links.                                                                                                                        | Not below `recoveryWindowMs` (tested).                                                         |
| `recoveryLinkGraceMs`         | 2s      | A dead member (still in membership) holding recovery open. Peers still linking are waited for this long.                                                                               | A live guest with a slow link is not waited for; its copy can be dropped.                                                                                | Leave. Below `recoveryMaxMs` (tested).                                                         |
| `resyncIntervalMs`            | 3s      | A dropped snapshot leaving a guest unsynced. Repeats only while unsynced.                                                                                                              | Extra snapshot requests while unsynced.                                                                                                                  | Cheap.                                                                                         |
| `pingTimeoutMs`               | 2s      | A duplicate-tab check hanging. No pong means ghost.                                                                                                                                    | **Destructive**: removes a live old tab slow to answer.                                                                                                  | No.                                                                                            |
| `duplicateRevealTimeoutMs`    | 4s      | A hidden newcomer staying hidden after a dropped resolution message.                                                                                                                   | Reveals before arbitration ends: a flicker.                                                                                                              | Above `pingTimeoutMs` (tested).                                                                |
| `helloIntervalMs`             | 3s      | The host's one-time status broadcast being dropped. Repeats only while pending.                                                                                                        | Extra hello messages while pending.                                                                                                                      | Cheap.                                                                                         |
| `linkWaitMs`                  | 8s      | Pinging before data-channel links are active.                                                                                                                                          | Arbitration starts before links are up; live tabs may be removed.                                                                                        | No. Cap on link setup.                                                                         |
| `departureGraceMs`            | 4s      | A refreshing player's row vanishing and returning.                                                                                                                                     | A slow reload shows as a new join instead of a rejoin.                                                                                                   | Lower makes a normal refresh flicker.                                                          |
| `hostClaimMaxAgeMs`           | 15s     | A stale pagehide stamp being trusted.                                                                                                                                                  | A slow reload falls back to the slow reclaim path.                                                                                                       | Leave.                                                                                         |
| `cookieMaxAgeSeconds`         | 24h     | Abandoned local profiles piling up.                                                                                                                                                    | Nickname forgotten sooner.                                                                                                                               | Leave.                                                                                         |

## Relations that must hold

Checked in `timer-inventory.test.ts`:

- `commandTtlMs` exceeds the failover budget (candidate window + confirm window + two position intervals + `recoveryMaxMs`).
- `duplicateRevealTimeoutMs` exceeds `pingTimeoutMs`.
- `recoveryMaxMs` is at least `recoveryWindowMs`.
- `messageRetentionMs` exceeds `ackTimeoutMs`; `candidateRetentionMs` exceeds the election budget; `roomRetentionMs` exceeds a day (TTL deletion lag).
- `probeIdleMs` is at least `probeTimeoutMs`.
- `recoveryLinkGraceMs` is below `recoveryMaxMs`.
